# Splat morph: shape-preserving and particle cloud

The Scene Editor previews two deterministic morph modes entirely in the browser. **Şekil koruyan** (shape-preserving) is the default for new morphs: nearby normalized regions correspond and splats move directly toward their partners. **Parçacık bulutu** retains v1's diffusion-inspired A → particle cloud → B effect, one selection away. Both are procedural effects. Defaults are shape-preserving, zero wave and arc, full target blend, six seconds and seed 42; cloud mode retains full dissolve.

## Try it

1. From this worktree's repository root, start its updated backend in the prepared `gs4d` environment: `python -m uvicorn backend.api:app --host 127.0.0.1 --port 8002`. This leaves the other worktree's backend on 8000 alone.
2. In a second terminal, run `cd frontend`, `npm install` if needed, then `npm run dev -- --port 1422`. Open **http://localhost:1422** and set the app's backend connection address to **http://127.0.0.1:8002**. This leaves the other frontend on 1420 alone.
3. Open **Sahne Editörü**. Open an existing scene with **Aç**, or upload/select a base `.ply` under **Yeni sahne** and click **Oluştur**. Under **Obje ekle**, upload/select another `.ply` and click **Sahneye ekle**. Start with about 200,000 splats per asset.
4. Position, scale, crop and colour the objects as desired. Select **A** on the source object's row and **B** on the target's row. These pair buttons leave the normal inspector selection intact. Keep both objects visible for a complete transition.
5. In the right-hand **Morph** panel, leave **Mod → Şekil koruyan**. Enable **Otomatik hizala** when the captures have different orientations, then click **Morph hazırla**. Wait for the count, preparation time and **ortalama yol** estimate, then **Oynat**. Alignment changes matching only: for an apple-to-orange style change, position the objects' centers and sizes in the editor first, and start with **Dalga = 0**, **Yay = 0**. Orbit the camera normally; object gizmos are suspended during preview. **Duraklat** pauses, **Başa dön** resets, and the timeline scrubs deterministically. Click or Tab into the viewport and press **Space** to play/pause; input fields and other editor controls retain their usual keyboard behavior.
6. Choose **Mod → Parçacık bulutu** for the original effect. Switching modes pauses, resets the timeline and automatically rebuilds an enabled preview with that mode's correspondence. **Dalga/Yay** or **Dissolve** edits update uniforms without rematching. **Önizlemeyi kapat** restores the normal scene. **A ↔ B** swaps the pair; prepare again. Changing seed or an endpoint's geometry/appearance prepares a new pairing. Leaving the Scene Editor pauses playback; deleting an endpoint or closing the scene ends the preview.

7. Click **Kaydet** to store A/B and the morph controls. Reopen the scene to restore them, then click **Morph hazırla** again. Older scenes without morph settings use the defaults.

The persistence schema requires this worktree's updated backend; a server from the earlier branch will reject the new optional field. See the README for additional backend configuration. Opening a scene file without morph metadata keeps the old behavior and defaults.

## Record a video

1. Open a scene with two visible splat objects, choose their **A** and **B** buttons, select **Mod**, and set **Süre (sn)**, **Dalga/Yay** (shape) or **Dissolve** (cloud), **Target blend** and **Seed**. Recording supports both modes and uses the same mode/wave/arc uniforms as preview.
2. Click **Morph hazırla** and wait for the particle count. Position the camera and set the viewport/window size before recording.
3. Click **Videoyu kaydet**. Recording always samples the complete timeline from 0 to 1, regardless of the current preview position. The button shows **Kaydediliyor… %NN**. Morph controls, pair/object editing, editor shortcuts and the camera are locked during recording.
4. Keep this tab visible and its viewport size unchanged. On success the browser downloads **`splat-morph-<seed>.webm`**. Its usual download settings determine the destination or prompt. There is no audio; the video contains the current viewport, without the editor panels or crop selection outline.
5. Click **İptal** to discard the recording without downloading. Completion, cancellation and errors restore the previous timeline position and play/pause state. Leaving the editor or hiding the browser tab cancels and preserves the existing inactive-editor pause behavior. Closing/unmounting the editor also cancels. A viewport resize stops the recording with an error; resize first and retry.

The browser must support `canvas.captureStream`, manual `CanvasCaptureMediaStreamTrack.requestFrame`, and WebM `MediaRecorder`. The encoder preference is VP9, then VP8, then plain WebM, checked with `MediaRecorder.isTypeSupported`. Unsupported browsers report a panel error. Recording uses the existing canvas pixel dimensions; v1 does not resize it or offer an FPS/resolution selector.

### Frame ordering and timing

- The fixed sampling rate defaults to **30 FPS**. For duration `d` and sampling rate `fps`, `intervals = round(d * fps)`, and the schedule contains **`intervals + 1`** samples at `t = i / intervals`, including exact 0 and 1. Six seconds therefore requests 181 frames. Normal wall-clock playback is paused; render stalls never skip or advance a timeline sample.
- Each sample updates the morph uniforms and endpoint visibility. At the first frame and at source/particles/target handoffs, two animation frames allow React to commit recording controls, crop-outline hiding and original-object suppression across the R3F root. Sorting does **not** rely on those waits: a dedicated Spark viewpoint explicitly updates the splats and awaits the public `SparkViewpoint.prepare({ update: false })` GPU readback/worker sort, then calls `gl.render(scene, camera)` and `requestFrame()` in the same turn. This works without `preserveDrawingBuffer`.
- The live R3F render loop and Spark auto-updates are suspended for this session; the recording owns every draw, avoiding intervening live renders and concurrent sorts on its viewpoint. Spark 0.1.10's manual `prepare()` retains an extra temporary accumulator reference; `morphCapture.ts` balances it through the public `releaseAccumulator()` API, separately from the display's own reference. Cancellation stops the encoder/tracks immediately, then lets any in-flight Spark sort settle before releasing its inputs and restoring the live renderer.
- `captureStream(0)` disables periodic capture. The stream and encoder are created only at the first prepared draw, so the stream's implicit initial frame also sees the start of the morph. Capture requests are paced with a minimum `1 / fps` interval: preparation/sorting overlaps that interval, then the final draw waits only for its remaining time. The last frame gets an interval plus a paint opportunity before recorder finalization. Only successful, nonempty recorder output triggers a download.
- **Timing limitation:** samples and seeded trajectories are deterministic; WebM bytes, encoded frame count and timestamps are controlled by the browser's real-time `MediaRecorder`. Rendering/sorting overhead and encoder load can lengthen the output beyond the configured duration or cause browser-level frame drops. This is not an offline constant-frame-rate exporter. Exact encoded duration/frame count would require a timestamp-controlled encoder/muxer beyond the requested MediaRecorder path. Large scenes and high canvas resolutions also increase recording time, memory and file size; chunks are held in memory until completion.

## Controls

| Control | Meaning |
| --- | --- |
| Mod | **Şekil koruyan** (default) uses spatial bisection and direct motion; **Parçacık bulutu** uses Morton rank matching and cloud motion. Switching rebuilds correspondence. |
| Otomatik hizala | Shape only, default off. Estimates a proper rotation for correspondence and rebuilds the preview. Does not rotate either object in the editor or allow reflections. |
| Duration / Süre | 0.5–120 seconds of active playback; large frame stalls are capped at 0.1 seconds so returning from a suspended tab does not skip the effect. |
| Dalga / Wave | Shape only, 0–1. A world +X sweep, normalized across the source's robust X extent, delays each source particle. Maximum delay is half the duration at 1; the motion window shortens accordingly, so the total duration and exact endpoints are unchanged. Default 0 moves all particles together. A flat-X source receives a common final delay. |
| Yay / Arc | Shape only, 0–1. A seeded perpendicular arc is bounded by `0.05 * pairDistance * arc`. Default 0 gives straight paths; identical positions stay still at every setting. |
| Dissolve | Cloud only, 0–1; controls bounded cloud displacement and shrinkage toward small isotropic particles. At 1 the full cloud appears at the midpoint; at 0 it directly interpolates the existing Morton pairs. |
| Target blend | 0–1; maximum global progress toward B. Effective progress is `timeline * targetBlend` before the wave delay: 0 holds A, 0.5 stops partway, and 1 reaches exact B. |
| Seed | Unsigned 32-bit integer; changes stable particle trajectories. Scrubbing, pausing and replaying never generate fresh randomness. |

**Ortalama yol** reports the mean straight-line distance between matched world-space endpoints, divided by the larger object's robust bounding-box diagonal (`2 * sceneRadius`, with a 0.002 floor), as a percentage. It includes invisible padding paths and measures full A → B travel, independently of the target blend, wave, arc or dissolve controls. It can exceed 100% for far-apart objects. This is a diagnostic of the actual paths; alignment can find exact normalized correspondences while the rendered endpoints still have substantial travel because their composer transforms differ. Recording stays disabled while correspondence is preparing or rebuilding.

## Save and export

`SceneDoc.version` remains **1**. The optional `morph` object stores `sourceId`, `targetId`, `mode`, `duration`, `dissolve`, `wave`, `arc`, `targetBlend`, `seed` and `autoAlign`. Omitted/null morph metadata loads normally, with the existing defaults; unknown scene versions remain rejected. Backend validation enforces finite control ranges, an unsigned 32-bit integer seed, boolean alignment, and distinct references to existing splat objects. A partial A/B selection is valid. Deleting either referenced object clears the entire saved morph and stops the preview gracefully.

Setting changes mark the scene dirty and are saved by **Kaydet** / **Ctrl+S**. Time, play/pause, preview enabled state, preparation buffers and recordings are transient. Opening a saved scene restores the recipe at time zero, stopped, with the preview disabled until **Morph hazırla**. Leaving the editor pauses a live preview as before.

**Export** saves the current scene snapshot first and carries the recipe in the ZIP's `scene.json`. Its baked PLY/GLB assets remain static and ignore morph settings. Export tests compare the baked PLY bytes with and without settings. **Videoyu kaydet** remains the separate way to download the animated viewport as WebM.

## Implementation and Spark API

- Confirmed against the installed **Spark 0.1.10** types and embedded sources/examples. Extraction uses `PackedSplats.getSplat`, applies local crop before the composer’s uniform scale/rotation/translation, composes splat quaternions and applies the existing DC colour matrix. Extraction yields every 4,096 splats; sorting/matching runs in a module worker with transferred buffers.
- Per-axis 2nd/98th percentiles produce robust bounds. Order-statistic selection replaces full sorting for these exact percentiles. With automatic alignment off, each side is centered and uniformly normalized by its longest robust dimension **for correspondence only**; the original pairing and output attributes are unchanged. Output positions retain the original composer transforms: B ends where the user placed it. No color term is used.
- **Optional automatic alignment:** normalize each full point set by its centroid and twice its RMS radius, which are rotation invariant (axis-aligned percentile boxes are not). Compute the full-set covariance/PCA with a deterministic Jacobi eigensolver. Score all **24 proper signed principal-axis permutations** with the same spatial-bisection matcher on at most **1,024 evenly spaced input indices** per side. Choose the lowest mean sample travel; fixed iteration order breaks ties deterministically. For different PCA spectra, try up to **three quaternion Horn/Kabsch rigid refinements**, retaining only lower-cost results. Equal spectra skip sample refinement to avoid disturbing an exact rigid-copy solution. Apply the selected proper rotation to B's temporary normalized coordinates only, then run the usual full-size pairing. No reflection, source mutation, or rotation of rendered endpoints occurs. Cloud mode ignores this toggle.
- Alignment adds O(N) full-cloud normalization/PCA/rotation work plus bounded sample searches, with O(N) temporary coordinates. Candidate scoring is an approximation of full matched travel, not an exhaustive full-million-point comparison for every rotation. Mean/RMS normalization and PCA are more sensitive to floaters than the off-path robust bounds. Repeated/near-equal eigenvalues, symmetric objects, spatially ordered sampling, different densities and unrelated topology can make orientation ambiguous or produce a local minimum. Turn alignment off if it worsens the pair; it defaults off and the original buffers are protected by golden SHA-256 tests captured from `e348246`.
- **Shape correspondence:** recursively bisect both normalized subsets in lockstep along the largest axis spread of their union. Split the larger subset at its median and the smaller at the matching rounded quantile, keeping both children nonempty. Deterministic, median-of-three in-place quickselect partitions index arrays instead of sorting every node, giving expected **O(N log N)** work and O(N) auxiliary storage. Full sorting at each node would add a log factor. Coordinate tie-breaks precede input-index ties, so shuffled identical point sets recover zero spatial travel. At a singleton leaf, pair it with the remaining local members; its real opacity belongs to the nearest member and the other copies have zero opacity. This is equivalent to continuing subdivision with invisible singleton clones.
- **Cloud correspondence:** retain the 30-bit Morton ordering/rank matching and adjacent-rank padding from v1.
- `N = max(NA, NB)` after crop in either mode. Every original is retained exactly once with its original opacity; extra clones contribute zero opacity at their padded endpoint. A hashed seed is stored per pair. Shape pairs also carry the clamped source +X projection in the reserved color texel component for the sweep.
- Two RGBA32F textures hold paired position/opacity, scale/seed, quaternion and DC colour. A custom dyno graph on **`SplatGenerator`** emits world-space `Gsplat`s. This avoids creating another packed source mesh and uses the generator API instead of a `SplatMesh` modifier. Each frame changes only uniforms and calls `updateVersion()`; there is no CPU particle loop or attribute upload.
- A mode uniform selects the motion branch without recompiling the dyno generator. **Shape motion:** let `p = clamp(t) * clamp(targetBlend)`, `w = 0.5 * clamp(wave)`, and `q = clamp((p - w * projection) / (1 - w))`. Interpolate with smootherstep `u = q³(q(6q - 15) + 10)`. Position follows the pair's straight segment, optionally displaced by the bounded perpendicular arc. Scales interpolate in log space, rotation by shortest-path quaternion slerp, color and opacity linearly in `u`; padded clones fade. Exact local and global endpoints bypass interpolation, including zero scales. No cloud displacement, shrinkage or opacity dip is applied.
- **Cloud motion:** unchanged eased interpolation plus bounded seeded sinusoidal turbulence. Displacement is at most `1.5 * robustRadius * dissolve * sin²(pi * progress)`. Scales shrink toward `0.0015 * robustRadius` at full dissolve; rotation uses shortest-path quaternion slerp. Color and opacity blend deterministically.
- The original source objects render at progress 0 and 1, preserving their original SH, crop, colour, placement and visibility. During the transition only DC colour is morphed. Spark can evaluate source SH, but v1 does not pair or interpolate SH coefficients, so view-dependent colour can change at the endpoint handoff. “Exact” refers to the original Spark-rendered object, including its existing packed precision.
- Worker cancellation, source cache ownership and preview GPU resources are cleaned up on rebuild/close. Spark 0.1.10 lacks a public generator disposal API; `morphDispose.ts` confines its version-specific cache access. Heavy buffers/materials are released; a small amount of shader metadata remains in Spark's inaccessible material cache until page reload.

This benchmarks the production worker's preparation function in Node; loading/extraction, worker startup/transfer and GPU upload are excluded. ### Shape-preserving correspondence (2026-10-07)

Reproduce from `frontend/` with **`node --expose-gc scripts/benchmark-morph.mjs`** (Node 22.18+ or 24; no additional packages). Fixture: independent random sphere surfaces with ±1% radial noise, seeds 12345/67890. Each scene is measured in its own robust normalized coordinates; distances include invisible padding paths. Timings include input validation, percentile bounds, normalization, matching, padding and output attribute copies; they exclude input generation, loading/extraction, worker startup/transfer and GPU upload. One 10k warmup, then three timed runs; medians below. Machine: **AMD Ryzen 5 5600X**, **Node v24.12.0**.

| A / B splats | Morton preparation | Shape preparation | Morton mean travel | Shape mean travel | Shape / Morton travel |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100k / 100k | 134.7 ms | 256.6 ms | 0.09773964 | 0.01251432 | 0.128× |
| 1M / 1M | 1,703.1 ms | 4,885.7 ms | 0.06881357 | 0.00503289 | 0.073× |
| 100k / 120k | 147.8 ms | 354.8 ms | 0.09968712 | 0.01260220 | 0.126× |

The Morton correspondence is unchanged from v1, but these current-baseline timings share the faster percentile selection. **The <2-second target for two 1M inputs was not achieved.** Machine-load variability was substantial: an earlier best shape run took 2,076.7 ms; the final 1M runs were 4,885.7 / 4,186.4 / 5,648.1 ms. Shape's final 100k runs were 266.6 / 232.4 / 256.6 ms. The table reports the final measured median, not the favorable earlier run. Preparation stays off the UI thread in the existing worker; this does not promise a two-second load time.

On the smaller **1,500 / 2,000** unequal-count fixture, mean travel is **0.26916147 Morton → 0.06440146 shape**. The trivial capacity-free nearest-neighbor lower bound is **0.02412029**: shape is 2.67× this bound and exceeds it by 0.040281 normalized units. That relaxation can reuse arbitrary source members, so it need not be attainable when all originals must survive. Shuffled identical inputs have **zero** measured positional travel, including coordinate ties. Tests require <0.5× Morton travel, <3× the nearest-neighbor lower bound, and <0.045 absolute excess on this deterministic fixture.

### Original cloud measurements

Measured on 2026-10-07 for v1:

- Pure pairing of synthetic **200k + 200k** records in Node v24.12.0: **371 / 413 / 419 ms**, three runs. This excludes loading, extraction, worker startup and GPU upload.
- A browser WebGL2 smoke test reported **NVIDIA GeForce RTX 3060 Ti / ANGLE D3D11**. At **960×640**, pixel ratio 1, with 200k synthetic sphere-to-cube particles, 90 animated frames had **13.9 ms median (~72 fps), 14.0 ms p95**. All three sampled progress values (0, 0.5, 1) produced distinct nonempty images without shader/WebGL errors. Fixture generation, pairing and texture setup took **1.93 seconds**. This was VSync-limited development rendering with `preserveDrawingBuffer`; real assets, SH, overdraw, other objects, resolution and browser load will differ.
- Estimated additional attribute storage at 200k pairs: **24.4 MiB GPU textures** plus their **24.4 MiB CPU backing arrays**. During preparation, input/output/sorting buffers add tens of MiB. Original assets/SH, Spark accumulation/sorting targets and framebuffers are additional; this is not a total VRAM measurement.

Both modes allow up to **1,000,000 raw splats per asset**, also subject to the GPU texture limit. Empty crops fail with a panel error; hidden endpoints contribute zero opacity. Spatial bisection reduces local travel but is an approximate geometric correspondence, not optimal transport or semantic matching. Partition boundaries, different densities/topologies and distant floaters can still produce crossings or less local pairs. Automatic alignment is approximate for unrelated or symmetric shapes. Quickselect has expected rather than worst-case O(N log N) total complexity. Normalization does not reposition the actual scene: large editor translations/scales still require large motions. There is no learned deformation, collision handling, SH interpolation or animated scene export. **Kaydet** preserves the morph recipe; static **Export** carries it as metadata, and **Videoyu kaydet** downloads the viewport animation. Start at 200k per side and reduce asset size/resolution if needed.
