feat(api): FastAPI backend + parse_colmap sub-model fix (Phase 7)

New files:
- backend/api.py — FastAPI app with 5 endpoints:
  POST /process, GET /status/{id}, GET /download/{id},
  GET /jobs, GET / (health with GPU info)
- backend/api_models.py — Pydantic models (Job, JobStatus,
  PhaseProgress, etc.)
- backend/job_manager.py — thread-safe in-memory job registry
  with ThreadPoolExecutor(max_workers=1) for GPU serialization

Changes:
- backend/pipeline.py: added optional progress_callback param,
  called at each phase boundary (non-breaking)
- backend/model/trainer.py: added optional progress_callback
  for iter-level training updates
- backend/preprocess/parse_colmap.py: _find_sparse_dir now
  auto-detects which sparse/N subdirectory has cameras.txt
  (previously hardcoded to sparse/0, broke when COLMAP
  produced multiple models and run_colmap picked a non-0 one)
- README.md: added HTTP API section with curl examples
- .gitignore: added .claude/settings.local.json and *.zip

Verified end-to-end via API smoke test:
- POST /process uploaded video, 202 Accepted + job_id
- GET /status showed queued -> running -> completed
  (phase progress: frames -> colmap -> init -> training -> export)
- GET /download returned 1.93 MB zip with 10 .ply files
- Total runtime ~70s (smoke config: 500 iter, 480x270, 10 ts)
